# AI Industry Build Prompt

Use this prompt when turning a fresh BusinessWeb copy into a customer site.

```text
这是一个可复用的 Astro 6 + Cloudflare Workers + Keystatic + Manager + R2/D1/KV 国际商业网站模板。

行业：
英文核心关键词：
其它目标语种：
公司名称或公开品牌：
商业模式（如已知）：
目标国家或市场（如已知）：
主要买家（如已知）：
公司资料（可后补；真实性由站长负责）：
图片或资料（真实资源或建设占位均可）：
需要留资下载的资料（可选；填写真实 PDF 名称与已核实 R2/CDN HTTPS 地址）：
旧站迁移 URL（仅在客户明确授权迁移时填写，建议使用“旧站迁移+网址”）：
指定参考站点（可选）：
指定参考模板/本地 HTML 样板名称（可选）：
参考对齐程度（启发 / 尽量一致；未提供设计参考时留空）：

执行要求：

第一阶段先盘点母版当前已批准工程基线：README 能力、真实 Keystatic 设置、schema/API/消费端、测试与能力账本，不只看 CAP 编号；登记来源 SHA。全新独立复制站保留全部已实现能力（含关闭功能），已有客户只移植获准范围；不复用母版/其它客户的 Git 身份、凭据和资源。
根据行业买家任务、资料、前置条件及成本/隐私影响决定可选功能默认开或关，在原客户进度表说明理由；未配置不等于未接入。缺可选资料/凭据时保留能力且关闭或未配置，不阻塞整个建站，不自动授权外部服务。
阶段一就做好前端与 Manager 的开/关、空数据及重新开启适配，站长首次进入 Keystatic 选择无需重做页面；隔离检查字段/路由/API/写回、导航/间距和 schema，不改真实开关来测试。产品评价独立于首页评分，关闭保留未发布草稿评价。
Keystatic 控制所有可选业务能力和站点策略，Manager 只维护被允许的内容；必需鉴权、安全及部署保障不设关闭开关。配置保存/发布仍按原流程生效；缺少真实控制项只登记缺口，工程实现另按“确认修改能力”门槛，不伪称已有。
业务真实性和素材授权由站长负责；提供/确认的资料直接采用，AI 不做常规真实性复审、外部举证或逐项占位登记。AI 只核对技术格式、产品对应、单位、关键缺项及矛盾，不编造未知事实。建设占位/示例可用，只在原进度文件简记范围和负责人，不增加后台必填字段或公开处理标签。
每次 push 前绑定真实 Git 根/common Git、HEAD/分支、映射 owner/repo、有效 fetch/push URL 和明确目标 ref；账号/origin 名字不能证明目的地。只允许一个预期 push URL，身份/refspec/URL 重写冲突就停这次写入；不改 origin 绕过，显式推 HEAD:refs/heads/<已授权目标> 并核对远端回执。

公共前端面向采购本站商品或服务的商业客户，正文、标题、图注、alt、SEO 字段及翻译只能服务介绍、规格选型、采购询价、合作交付和售后。禁止数据/媒体来源、导入提取、AI 核实、示例状态及任务完成说明，如“数据来自目录”“AI已核实”；这些只写内部记录。两阶段和维护都遵守；正常目录下载、系列名及必要署名保留，不机械禁词。验收时检查页面/图注/alt/SEO 和翻译，不能只检查代码能否构建。

导入媒体先核对产品/型号、产品图与内容插图，以及完整图文组合；曲线图保留全部图例、单位和型号。解释性插图紧接对应文字段落上方；若对应的是整组特性卡片、步骤或表格，则放在整个模块之前，绝不把模块拆散。产品照片放图库。先验代表页，再批量处理并检查桌面/手机及受影响语种；不改真实参数。

进度不是流水账：批量内容/媒体、发布、回退相关变化或未完成任务才按 AGENTS 记一条；下载、转码、重试和清理不单独记。紧急保站不因此强制做无关的改写或重排。

状态与交接合并在客户原有 docs/PROJECT-PROGRESS.md：开始先读顶部状态和相关交接，接入、配置、开关、实际验证分开登记，只更新受影响的行；主动关闭、未核查、站长暂缓不自动变成启用任务。README 写给站长和管理员，只保留稳定功能、部署和使用步骤；只有用法变化才改，不能写 AI 本次汇报、开关现状、缺凭据或催办提醒。工程来源/兼容/回退留在原能力账本，不新建状态文件。


1. 先完整阅读 README.md、AGENTS.md、docs/CODEX-INDUSTRY-WORKFLOW.md、docs/ASTROWIND-INTEGRATION.md、docs/PUBLIC-VISUAL-FOUNDATION.md 和 .agents/skills/businessweb-seo-geo/SKILL.md；提供旧站迁移 URL 时还要阅读 docs/OLD-SITE-MIGRATION.md。
2. 在编辑任何文件前，先把本次全部要求逐项列入以下四类，并写明将落到哪些文件；没有完成归类不得开始实现：
   - A｜Codex 第一阶段决策规则：迁移触发词、研究顺序、输入职责、真实文案处理、原 URL 策略、R2 key 语义原则、受控下载是否启用及页面位置、视觉参考优先级、交互 QA、验收标准和“确认修改能力”门禁。这些只进入 AGENTS、Skill、流程文档和本提示词，不得变成买家页面上的运行时代码或文案。
   - B｜母版通用工程能力：跨客户、跨行业都能以确定输入产生确定输出的抓取、解析、逐页归档、映射、R2 上传、路由审计、共享 CAPTCHA、公开表单 D1/Resend 双写、可配置下载白名单和预览部署门禁。这些才可以进入母版代码、scripts、tests、package scripts 或 CI；实现中不得带客户域名、客户 slug、客户文案、客户文件、行业皮肤或参考站样式。
   - C｜客户项目公共层实现：该客户的页面与组件、原 URL 路由、真实内容、元数据、媒体/CDN 引用、行业视觉、交互和动效。第一阶段可在既有工程接口内彻底重构这些文件，但它们只属于从母版创建出的客户仓库，不等于修改母版工程能力。
   - D｜客户数据产物：/oldsite 原始归档、逐页媒体目录、客户 R2 manifest、旧 URL 映射、抓取报告和客户核实记录。这些只能生成在客户项目的忽略目录或客户数据目录，禁止提交为母版默认内容。
   同一项要求同时包含规则与执行能力时必须拆分。例如“旧 URL 原样作为主路由”写入 A，通用构建后路由核验器写入 B，客户的实际路由写入 C，客户 URL 映射写入 D；“R2 key 使用原页面 slug 与真实图片语义”写入 A，稳定 key/manifest/upload.ps1 生成器写入 B，客户 key 清单写入 D。无法明确归类时停止编辑并先说明冲突。
3. 保持英语为源语言；其它语言只能从 src/data/site-language-settings.json 启用。
4. 先运行 industry:brief，但不要立即开始套颜色或改首页。
5. 必须先调查当前行业。通常研究至少 5 个真实站点，其中至少 2 个是行业领先企业或直接竞争者。可以审计本地 astrowind-main 的 Astro 组件和性能实现，但 AstroWind 不是固定皮肤。
6. 分析并记录：导航、首屏、产品或服务分类、详情页、图片比例与排序、文字层级、配色、模块节奏、询盘路径、移动端和动效。
7. 严格区分输入职责：母版只提供工程能力；客户明确授权的旧站只提供真实信息架构、文案、产品参数、元数据、媒体和原 URL；指定参考站只提供样式、布局、交互、动效和颜色方向。除非客户明确把旧站同时指定为视觉参考，否则不得沿用旧站视觉层。
8. 提供“旧站迁移+网址”时，必须先把旧站全部公开页面、原始 HTML、信息、参数、元数据、JSON-LD、图片、文档和媒体尽可能完整地保存到项目 /oldsite，并创建页面到媒体、原文件到 R2 key、旧 URL 到新主路由三套映射；生成按页面分文件夹的管理目录、Wrangler R2 上传包、upload.ps1 和手把手指引。新站保留所有可行的旧 pathname（含 .html）作为主路由；路径完全一致时不增加 301。新站运行时不得依赖旧站主机或旧 CDN。
9. 迁移站的第一阶段必须把旧站的信息架构与信息层、已核实真实文案、产品参数、元数据、媒体和原 URL 实际应用到新站，不得用母版演示内容替代。旧站逐页真实文案是唯一的内容改写底稿；Google 排名靠前的同行业页面只用于研究买家语言、专业术语、信息密度和句式节奏，不是新文案的事实来源。Codex 必须在旧站原文基础上逐页改写和去 AI 化，严禁抛开旧站原文、仅依据排名站点的语言风格从零生成页面文案。产品参数、事实、联系方式和证据必须保持原意与准确性；改写不得制造新主张、遗漏关键事实或抄写竞争者文案。旧元数据可在保留搜索意图与页面对应关系的前提下复用和优化。
   迁移站实施顺序固定为：完成旧站归档与盘点；建立旧页面到新主路由、页面到内容、页面到媒体、原文件到 R2 key 的映射；研究当前 Google 靠前同行业页面的语言特征；逐页保留事实并改写表达；按旧 pathname 建立页面；接入本项目媒体映射；复用或谨慎优化元数据、canonical 与结构化数据；最后运行旧路由、内容、媒体和 SEO 对应关系审计。不得先用演示内容做完整站点后再遗漏式替换。
10. 根据用户是否给出设计参考走不同分支：
   - 没有提供参考站 URL、本地样板或模板名称：AI 自主调查当前行业、竞争者和优秀相邻站点，结合买家任务独立确定视觉方向，沿用原来的“先研究、后设计”流程。
   - 提供了参考但要求“启发”：把参考作为视觉方向输入，吸收其可泛化原则，同时自主完成页面系统。
   - 提供了参考并要求“尽量一致”“对标”或“照搬视觉”：以指定站点/样板为主要视觉权威，尽量对齐其页面结构、模块顺序、空间节奏、图片比例、配色关系、字体气质、控件、悬停和动效，并覆盖首页及全部子页面。
   三种分支都必须继续调查行业事实和买家需求。不得复制对方文案、Logo、商标或第三方图片；要使用当前项目内容和自有/占位素材。
11. 在开始修改视觉前，明确写出：
   - 买家第一眼必须看到什么；
   - 适合该行业的视觉原型；
   - 首屏、导航和全站模块方向；
   - 字体、配色、图片和动效规则；
   - 必须删除的模板效果和不适合该行业的模块。
12. 允许彻底重写所有公共页面、组件和样式，不要被原模板或 AstroWind 演示页布局限制；但严禁破坏或替换 Astro 6、Cloudflare Workers adapter、静态资源优先路由、/keystatic/、/manager/、R2、D1、KV、翻译、共享 CAPTCHA、联系表单、询盘车、公开表单 D1/Resend 双写、可配置受控下载、SEO、分析、发布与 GitHub 写回能力。
13. 如确实需要修改技术栈、母版工程能力、应用边界或部署职责，先停止编辑，向客户说明原因、现状、修改后差异、受影响文件/系统、迁移成本和对 main 的风险；必须等待客户原样回复“确认修改能力”后才能修改。公共视觉在既有接口内重构不属于能力修改。
14. 新增的可复用工程组件类名必须描述通用角色或状态，例如 site-header、product-card、is-active；不得把客户名、行业名、旧站名、参考站名、颜色名或临时效果名写入可移植能力。Golden One 已有公共视觉类名属于客户视觉资产，不得在能力迁移中机械重命名。
15. 建设示例由站长在正式上线前替换或删除；不冒充平台真实评价，不加演示/已核实模式、来源证明或 SEO 资格开关。Keystatic 评价总开关关闭时两个产品编辑器隐藏评价字段且保留资料；开启并保存发布后，在产品内填评价人、1–5 星、内容和选填日期，已发布可见评价自动生成该产品 Review JSON-LD。首页评分与产品评价独立，首页留空不阻挡产品评价。 站长在 Keystatic 选择默认产品/服务类型与型号策略，可设置产品例外；Manager 只读该策略并维护内容，API 和写回均不得被旧草稿覆盖。
16. 产品或视觉驱动行业必须以图片冲击力和真实对象为主要信号；技术行业则以选型、参数、应用和证据为主。不要把不同商业模式做成同一种工业目录。
17. 不要默认使用水波、WebGL、毛玻璃、渐变装饰球、全站卡片墙、分栏式营销首屏或隐藏后再模糊出现的动画。
18. 动态文字必须服务于产品、材料、工艺、用途或结果表达；基础内容在 JavaScript 失败时仍必须可见，并支持 prefers-reduced-motion。
19. 对全部公开页面执行视觉层和交互检查：导航与二级菜单的鼠标过渡区、键盘焦点、移动菜单、轮播、图库、标签、筛选、折叠、分享、数量控件、询盘车、表单校验、CAPTCHA 加载/刷新/过期、加载/成功/错误状态、触摸、拖动、Escape、返回前进、悬停与 focus-visible 都必须可用。每个有效公开表单都应把来源页面和投递状态写入 D1 并通过 Resend 发到 CONTACT_TO_EMAIL。删除重复模块标题、模板遗留样式、公式化 AI 文案和与全站不一致的联系/转化模块。
20. `src/data/catalog-downloads.json` 在母版中必须保持 `enabled: false` 且文件列表为空。只有客户明确要求留资下载并提供已核实的 PDF 名称与 R2/CDN HTTPS 地址时，才在客户项目的 Keystatic **受控下载**中填入白名单，根据买家流程选择页面并接入 `CatalogDownloadGate.astro`，确认 D1、Resend 和 CAPTCHA 后开启总开关并明确发布。没有资料或需求时保持关闭，不创建空白下载模块；初始 HTML 不得暴露文件直链。
21. 完成后用浏览器检查桌面 1440x900、1024x768，移动端 390x844、360x800；检查导航对齐、溢出、图片、文字、控制台和 computed blur/backdrop filters。
22. 运行 npm run check、npm run check:template、npm run build，并修复全部错误；有旧站迁移时再运行 npm run oldsite:audit。
23. 最终报告必须先列出 A/B/C/D 四类实际改动，再报告视觉决策、旧站迁移覆盖率、未核实资料、路由差异和验证结果；无需记录每张占位图片的来源。
```

## SEO/GEO follow-up prompt

After the webmaster supplies or accepts content for the pages being optimized:

```text
全站 SEO 和 GEO 优化。
业务资料以站长提供/确认范围为准，不要求 AI 再核验真实性；没有可选价格、认证或评价不阻塞其它 SEO。保留技术有效性、可见内容一致性与安全检查。沿用阶段一工程基线和现有开关，SEO 任务不授权全量升级；每次 push 仍执行 AGENTS 的仓库身份核对。
行业：
英文核心关键词：
目标市场：

先调查最新 Google Search Central 官方文档、当前目标市场 SERP、买家问题和真实竞争页面，再建立关键词到页面的意图映射。只能使用已核实的产品、公司、价格、认证、案例和评价资料。完成后运行 check、check:template:production、check:seo 和 build。
公开优化结果仍写给买家，不展示 AI 处理说明；媒体先识别产品与完整图组，解释性插图放对应文字上方，整组卡片/步骤/表格保持连续，不能借 SEO 拆模块或改真实参数。进度按 AGENTS 选择性记录批量变化、发布/回退或待办，不记操作流水账。
先读客户 docs/PROJECT-PROGRESS.md 的当前状态与相关交接，只更新本轮涉及状态；README 只在稳定功能/部署/使用方法变化时更新，不作 SEO 工作汇报或待办提醒板。
```
